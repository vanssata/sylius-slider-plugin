# Regenerating the documentation media

Every screenshot in `docs/screenshots/` and every animation in `docs/media/` is
generated by Playwright and committed to the repository. Nothing is captured by
hand. One command rebuilds all of it:

```bash
make docs-media
```

The generators are not tests. They assert almost nothing; they drive the real
application and write image files. They live in their own Playwright project so
a normal test run does not overwrite committed assets.

## Layout

| Path | Contents |
| --- | --- |
| `tests/e2e/docs/admin.docs.spec.ts` | 11 admin screenshots, 5 admin GIFs. |
| `tests/e2e/docs/storefront.docs.spec.ts` | 2 storefront screenshots, 2 storefront GIFs. |
| `tests/e2e/docs/support/media.ts` | `freezeMotion`, `shot`, `recordGif`, `hold`, `responsiveViewportFrame`, `setStageWidth`, and the frame-size assertion. |
| `tests/e2e/support/data.ts` | Fixture contract: slider/slide codes, breakpoint viewports, route builders. |
| `tests/e2e/support/admin.ts` | `loginAsAdmin`, `sliderIdByCode`, `slideIdByCode`. |
| `docker/playwright/Dockerfile` | Runner image: Playwright base image plus `ffmpeg`. |
| `playwright.config.ts` | The `docs-media` project and the shared determinism settings. |
| `Makefile` | `docs-media`, `e2e-up`, `e2e-down`. |

Output goes to `docs/screenshots/<name>.png` and `docs/media/<name>.gif`,
resolved from `tests/e2e/docs/support/media.ts` relative to the repository root.
Intermediate GIF frames go to `var/docs-media-frames/<name>/` and are deleted
when the clip is assembled; `/var/` is gitignored either way.

## Prerequisites

The generators do not set the application up. Four conditions must hold before
`make docs-media`, and getting any of them wrong produces media that looks
plausible but is wrong.

### 1. The stack runs with `APP_ENV=prod`

Screenshots must not contain the Symfony web debug toolbar.
`compose.override.dist.yml` (copied to `compose.override.yml` by `make init`)
passes `APP_ENV: ${ENV:-prod}` to the `php` service, but the `Makefile` defaults
`ENV` to `dev`, so a plain `make up` gives you a toolbar. Pass `ENV` explicitly:

```bash
ENV=prod make up
```

### 2. The `prod` database exists and holds the fixtures

`DATABASE_URL` is `mysql://root@mysql/sylius_%kernel.environment%`, so `dev` and
`prod` use **different databases**. Fixtures loaded into `sylius_dev` are
invisible to a `prod` stack. Every fixture-related target therefore needs the
same `ENV=prod`:

```bash
ENV=prod make database-init          # or database-reset to start clean
ENV=prod make load-fixtures          # stock Sylius: channel + admin user
ENV=prod make load-slider-fixtures   # suite vanssa_sylius_slider_demo
```

Both fixture loads are required. The plugin's demo suite
(`vanssa_sylius_slider_demo`, a single fixture `vanssa_slider_demo`) creates only
sliders and slides; it writes no `StylePreset` rows — the presets it seeds them
from live in configuration. The storefront channel and the
`sylius@example.com` / `sylius` admin account used by `loginAsAdmin` come from
the stock Sylius fixtures.

The demo data is what the generators address by code, never by id — the specs
resolve numeric ids at runtime through `sliderIdByCode()` / `slideIdByCode()`
because a fixture reload changes them. Codes in play: sliders
`fashion-classic-arrows`, `fashion-minimal-fade`, `fashion-autoplay-showcase`,
`fashion-fullscreen-hero`, `fashion-compact-banner`,
`fashion-parallax-showcase`; slides `new-collection`, `summer-dresses`,
`denim-essentials`, `graphic-tees`, `street-caps`, `season-sale`,
`runway-video`.

### 3. The frontend bundles are current

The captured UI is whatever the compiled bundles render. Either run the watcher
and let it settle, or do a one-off build — never both at once:

```bash
make node-watch && make node-watch-logs     # watcher, or:
make node-build                             # one-off
```

### 4. The Playwright container is up

`make docs-media` depends on `e2e-up`, which starts the `playwright` service
(compose profile `e2e`) and installs the Node dev dependencies inside it on
first use. The service joins the host network, because every Sylius channel in
this project has hostname `localhost`; from inside the compose network the app
is only reachable as `http://nginx`, which resolves to no channel and 404s.

Stop it when you are done:

```bash
make e2e-down
```

## What the command runs

```bash
docker compose --profile e2e exec -T playwright \
    npx playwright test --project=docs-media --reporter=list
```

The three assertion projects never pick the generators up: `desktop` sets
`testIgnore: ['docs/**']`, and `tablet` / `mobile` only match
`shop/**/*.spec.ts`.

`make e2e` does not touch the committed media: its target names the three
assertion projects explicitly, because a bare `npx playwright test` selects
every configured project — `docs-media` included, whose specs overwrite the
committed screenshots and GIFs.

```make
E2E_PROJECTS = --project=desktop --project=tablet --project=mobile

e2e: e2e-up
	@… npx playwright test $(if $(findstring --project,$(ARGS)),,$(E2E_PROJECTS)) $(ARGS)
```

Passing your own `--project` in `ARGS` suppresses that default list, so
`make docs-media` remains the only command that regenerates the media.

## What makes the output deterministic

A committed image should change only when the UI changes. Everything below
exists to remove a source of run-to-run noise.

| Lever | Where | Removes |
| --- | --- | --- |
| `APP_ENV=prod` | compose `ENV` | Web debug toolbar, dev-only markup. |
| `locale: 'en-US'` | `playwright.config.ts` `use` | Locale-dependent labels and formats. |
| `timezoneId: 'UTC'` | same | Rendered dates shifting with the host clock. |
| `colorScheme: 'light'` | same | A dark-mode capture on a dark-mode host. |
| `viewport: 1600x950` | `docs-media` project | Layout reflow between runs. |
| `workers: 1`, `fullyParallel: false` | `playwright.config.ts` | Races on the single shared fixture dataset. |
| `video: 'off'` | same | Stray `.webm` artifacts. |
| `mode: 'serial'` | `admin.docs.spec.ts` | Ordering effects between admin captures. |
| `freezeMotion(page)` | `support/media.ts` | Mid-animation stills, blinking carets, smooth-scroll offsets. |
| `animations: 'disabled'` | every `page.screenshot()` | An in-flight transition smearing a frame. |
| Codes, not ids | `support/admin.ts` | Hard-coded ids breaking after a fixture reload. |

`freezeMotion` injects a stylesheet that zeroes animation and transition
durations and delays, caps `animation-iteration-count` at 1, makes the caret
transparent and forces `scroll-behavior: auto`. It is applied to the screenshot
generators and deliberately **not** to the GIF generators — motion is the point
there, and it is produced by the scripted steps, one captured frame at a time.

## Screenshots

`shot()` accepts a `Page` or a `Locator` and writes
`docs/screenshots/<name>.png`. A `Locator` crops to that element, which is how
the admin captures exclude the Sylius sidebar (`CONTENT` in `admin.docs.spec.ts`
is `.page-wrapper, main, .page-body`) and how the storefront captures crop to the
slider region.

```ts
await page.goto(routes.adminSliderIndex);
await freezeMotion(page);
await expect(page.getByRole('row').filter({ hasText: SLIDERS.classicArrows })).toBeVisible();
await shot(page.locator(CONTENT).first(), 'admin-sliders-index');
```

Wait on a role-based locator before capturing, never on a fixed sleep, or the
capture races the page.

The `docs-media` project viewport (1600x950) is the default, not a constraint: a
generator may call `page.setViewportSize()` before a capture, and the storefront
screenshots do exactly that to produce the desktop and mobile pair from
`VIEWPORTS`. Inside `recordGif` the viewport must stay fixed — see below.

## GIFs

`recordGif()` takes an explicit list of steps, captures one PNG frame before the
first step and one after each subsequent step, then hands the sequence to
`ffmpeg`:

```bash
ffmpeg -y -loglevel error \
    -framerate <fps> \
    -i var/docs-media-frames/<name>/frame-%04d.png \
    -filter_complex '[0:v] split [a][b];[a] palettegen=stats_mode=diff [p];[b][p] paletteuse=dither=bayer:bayer_scale=3' \
    -loop 0 \
    docs/media/<name>.gif
```

Two decisions behind that command:

- **Explicit frames instead of Playwright video.** Playwright can record
  `.webm`, but its frame timing is variable: the same scripted interaction
  produces a different file on every run. For a committed asset that should only
  change when the UI does, that is unusable. Driving the frames from the spec is
  reproducible.
- **`palettegen` / `paletteuse`.** A GIF is limited to 256 colours. Without a
  per-clip optimised palette, quantisation of a screenshot-heavy admin UI bands
  badly, especially across gradients and image slides. `stats_mode=diff` weights
  the palette towards the pixels that actually change between frames.

`ffmpeg` is installed in the runner image (`docker/playwright/Dockerfile`) — it
is not available anywhere else in the stack, and it is the reason the docs media
cannot be generated from the `nodejs` service.

`hold(n)` inserts `n` no-op steps, i.e. `n` extra identical frames. GIF playback
needs a pause on the result frame or the reader never sees it. Default `fps` is
8; the current generators use 4 (admin) and 6 (storefront). `clip` restricts
every frame to a fixed rectangle, used by `storefront-slider` to frame the
slider region.

```ts
await recordGif(
    page,
    'admin-workspace',
    [
        ...hold(3),
        async () => {
            await settings.click();
            await page.waitForTimeout(500);
        },
        ...hold(4),
    ],
    { fps: 4 },
);
```

### Every frame must be the same size

`ffmpeg`'s `image2` demuxer silently **drops** frames whose dimensions differ
from the first one. A generator that resizes the viewport mid-recording produces
a three-frame GIF and no error at all. `assertUniformFrameSize()` reads each
frame's PNG `IHDR` header and throws instead:

```text
GIF "responsive-breakpoints": frame frame-0005.png is 390x844 but the first
frame is 1400x900. ffmpeg would silently drop the mismatched frames. Keep the
capture canvas constant — to show breakpoints, resize an iframe inside a fixed
viewport (see responsiveViewportFrame) rather than calling page.setViewportSize().
```

Therefore a GIF that demonstrates breakpoint behaviour must **not** call
`page.setViewportSize()` between frames. `responsiveViewportFrame()` replaces the
page body with a fixed-size stage hosting the target URL in an `<iframe>`, and
`setStageWidth()` animates that iframe's width. The iframe's own width drives the
CSS media queries inside it, so the simulated device changes while the capture
canvas stays constant. This is the same technique the plugin's admin preview
panel uses for its resolution switcher.

```ts
await page.setViewportSize({ width: 1400, height: 900 });
await responsiveViewportFrame(page, routes.shopSlider(SLIDERS.classicArrows), 820);

await recordGif(page, 'responsive-breakpoints', [
    ...hold(4),
    setStageWidth(page, VIEWPORTS.tablet.width),
    ...hold(4),
    setStageWidth(page, VIEWPORTS.mobile.width),
    ...hold(5),
    setStageWidth(page, VIEWPORTS.desktop.width),
    ...hold(2),
], { fps: 4 });
```

`responsive-breakpoints.gif` documents the per-breakpoint layout overrides on the
`new-collection` demo slide — tablet centres the content horizontally, mobile
also centres it vertically. It is the only demo slide carrying such overrides, so
pointing that generator at another slide yields three identical-looking widths.

## Adding a new capture

1. Add a test to `tests/e2e/docs/admin.docs.spec.ts` or
   `storefront.docs.spec.ts` — a new file in `tests/e2e/docs/` is picked up
   automatically by the project's `testDir`.
2. Address fixture data through `SLIDERS` / `SLIDES` / `routes` from
   `tests/e2e/support/data.ts`, never a literal id or URL.
3. Screenshots: call `freezeMotion(page)` after the page settles, wait on a
   role-based locator, then `shot(...)`. GIFs: skip `freezeMotion`, script the
   steps, add `hold(...)` around the interesting frame.
4. Name the file after what it shows; the name is the filename, so it must not
   collide with an existing asset.
5. Regenerate, then reference it from a document. From `docs/usage/*.md` the
   relative paths are `../screenshots/<name>.png` and `../media/<name>.gif`.

```ts
test('slider settings drawer, behavior section', async ({ page }) => {
    const id = await sliderIdByCode(page, SLIDERS.autoplayShowcase);
    await page.goto(routes.adminSliderEdit(id));

    await expect(page.locator('.vanssa-workspace')).toBeVisible();
    await freezeMotion(page);

    await page.getByRole('button', { name: 'Settings' }).first().click();
    await expect(page.getByRole('button', { name: /Autoplay/i }).first()).toBeVisible();

    await shot(page, 'admin-slider-autoplay-section');
});
```

## Reviewing the result

PNGs and GIFs are binary, so `git diff` tells you nothing useful — inspect the
files. `git status` after a run is the honest signal: only the media you meant to
change should appear.

Unexpected diffs across *all* files usually mean one of the prerequisites
drifted: a `dev` stack (toolbar visible), stale bundles, or fixtures reloaded
between the previous generation and this one. Re-check the four prerequisites
before committing a whole-directory churn.

Regenerating is cheap; leaving the media stale is not. Any change to admin
layout, storefront markup, presets or demo fixture data invalidates the affected
captures.

## Troubleshooting

| Symptom | Cause |
| --- | --- |
| Debug toolbar in the screenshots | The stack runs `APP_ENV=dev`. Restart with `ENV=prod make up`. |
| Login fails, or a spec cannot resolve a slider id | Fixtures were loaded into the `dev` database. Reload them with `ENV=prod`. |
| Every shop page is a 404 | The runner is not on the host network, so requests hit a host that matches no Sylius channel. |
| GIF has three frames | Frame sizes diverged. If `assertUniformFrameSize` did not fire, the frames were assembled outside `recordGif`. |
| GIF colours band badly | The `palettegen`/`paletteuse` filter was dropped from the `ffmpeg` call. |
| `ffmpeg: not found` | The generator is running outside the `playwright` service; only that image installs `ffmpeg`. |
| Captured UI does not match the source | Bundles are stale — check the watcher, or run `make node-build`. |
| Regenerated media is not writable on the host | The `playwright` service ran under the default `DOCKER_USER` (`1000:1000`) instead of your UID/GID. Go through the `make` targets, which pass `id -u`/`id -g`. |
